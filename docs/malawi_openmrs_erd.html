programsdev.malawi - OpenMRS data model (ERD)

Multi-site OpenMRS consolidation. Patient-side tables are site-scoped: keys are composite with site_id. Verified Nov 2026.

        string name

Legend

  • ||--o{ one to zero-or-many; ||--o| one to zero-or-one; }o--o{ many to many (concept_name has several names per concept).
  • Multiple PK markers on a table = composite key (e.g. patient_id + site_id).
  • Every site_id references location.location_id; only the patient edge is drawn to keep the diagram readable.
  • Dictionary tables (no site_id): location, encounter_type, order_type, drug, arv_drug, program, program_workflow, program_workflow_state, concept_name.

General notes

  • No voided columns on patient-side tables in this copy; all date columns are STRING (cast with DATE()/to_date).
  • Some programme 1 state concepts (1483, 1710, 1713, 3490, 5240) have no concept_name rows.
